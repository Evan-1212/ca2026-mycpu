# The journey of the phone (software/programs/phone), for the host oracle
# (tests/phone/host) and for the harness (+phone-script). Portrait 240x320.
#
# Each line is a command; blank lines and lines starting with # are ignored.
# The commands are turned into events, one at a time, exactly so:
#
#   tap X Y        two events: DOWN (type 1) at X Y, then UP (type 3) at X Y
#   pointer T X Y  one event of type T (1 down, 2 move, 3 up) at X Y
#   key N          one KEY event (type 4), value N: ASCII, or 256 back, 257 home,
#                  258 tab, 259 left, 260 right, 261 up, 262 down, 263 enter
#   text STRING    one KEY event for each byte of STRING (after one space)
#   tick MS        one TICK event (type 5), value MS, 0 to 65535
#   expect F V     the host oracle checks the application's state: field F is
#                  V; the harness ignores the line (F: screen, value, error,
#                  position, score, theme, selected)
#   capture NAME   the picture after the events so far is saved as NAME.ppm
#
# The event word is type << 28 | X << 16 | Y for the pointer (X, Y in 0..511) and
# type << 28 | N for key and tick; the program splits it back into cp_event's
# arguments (type, word >> 16 & 511, word & 511, word & 65535). After every
# event the program renders once and presents once.
# A screen change is revealed in ten strips, one for each tick; "tick 0" moves
# the strips on without moving any clock.
